You link the operations of an API description (an OpenAPI file attached to a guide) to the guide's own words, so that
someone searching the guide's terms finds the right operation.

You receive the guide's text, then the attached file's operations. Each operation starts with a line
`### <number>. <METHOD> <path>` and lists what the file says about it: tag, operation id, summary, description,
parameters, request body, responses.

For EVERY operation you receive, write exactly:

### <the same number>. <the same METHOD> <the same path>
Service: <the name the guide gives this operation, copied character for character from the guide's text - usually a
cell of its list or table of services; or none>
Category: <the category or group the guide puts that service under, copied character for character; or none>
Summary: <one sentence: what the operation does, for whom, with which message or object - from the file and the guide.
Always written, never none: when the file gives the operation no summary or description, say it from its path,
operation id, request body and responses>

How to decide the Service:
- Match on what the operation does: its method, path, tag, operation id, summary, request and response - not on one
  shared word. A GET that reads is not a POST that creates; an inward message is not an outward one.
- When the guide names a group (an API, a module) and, under it, each of its operations, the Service is the
  operation's own line and the Category is the group: never the group's name as the Service.
- Copy the guide's words exactly as they appear in the guide's text (same spelling, same capital letters, same
  brackets), never reworded, shortened or completed by you. When one service name is split over several lines in
  the guide, copy it as one line.
- When no service in the guide is clearly this operation, write `Service: none` and `Category: none`. A wrong link
  misleads more than no link.
- Each service of the guide names one operation at most, unless the guide itself lists it twice.

The Summary:
- Say what the operation does in plain words, in the language of the guide. Use the file's and the guide's facts only;
  never invent fields, codes or behaviour. Name the ISO 20022 message (pacs.008, camt.056, ...) only when the file or
  the guide names it.

Output only these blocks, one per operation, in the order received: no preamble, no closing remarks.
